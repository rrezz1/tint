REST si ta shpjegosh dhe si ta dizajnosh

Resource = send (user, order), jo veprim. URL emër, metoda veprim.

Keq: POST /createUser. Mire: POST /users.

Stateless: cdo request mban auth. Serveri nuk mban “ku mbeta”.

Users API — thuaje me ze

GET    /api/v1/users?page=1&limit=20
GET    /api/v1/users/12
POST   /api/v1/users
PATCH  /api/v1/users/12
DELETE /api/v1/users/12

Body POST: {"email":"...","name":"..."}. Kurr password ne GET. Hash ne DB.

Gabim i qarte: {"detail": "email already used"} jo HTML 500.

Pagination

?page=2&page_size=20 ose cursor. Kthe count + results. Pa pagination, tabela e madhe e vret API.

Versionim dhe filter

/api/v1/ nese prish kontraten. Filter: /users?is_active=true.

Headers

Content-Type: application/json. Auth: Authorization: Bearer TOKEN ose cookie session.

Nuk eshte REST, por te pyesin

GraphQL: nje endpoint, klienti zgjedh fushat. WebSocket: realtime. Junior: “i di, nuk i kam thelle.”
